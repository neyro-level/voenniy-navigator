# PASSPORT_PROJECTS — Военный навигатор

## 1. Что это

Персональный сайт Михаила Хряпина, эксперта по военной ипотеке в Краснодаре.

Сайт помогает военнослужащим выбрать новостройку под задачу, получить подборку ЖК и пройти маршрут покупки по военной ипотеке.

## 2. Тип проекта

- Клиентский Astro-проект АМС.
- Клиент / публичный эксперт: Михаил Хряпин.
- Рабочая папка: `C:\Users\User\Desktop\Сборка АМС\Военный навигатор (AMS)`.
- Режим работы: сопровождение и доборка страниц/блоков по существующим брифам.
- Деплой: AMS Server (Timeweb Cloud, `5.42.100.161`) via GitHub Actions → `voen-navigator.ru`.

## 3. Стек

- Astro 5.
- Tailwind CSS v4.
- TypeScript strict.
- React islands только для интерактива.
- Lucide React.
- pnpm.

Команды:

```bash
pnpm install
pnpm dev
pnpm build
pnpm preview
```

## 4. Что читать первым

1. `PASSPORT_PROJECTS.md`.
2. `WORKLOG.md`.
3. Глобальные Astro/Codex-правила из настроек Codex и AI-SYSTEM.
4. `SITE_ARCHITECTURE.md`.
5. `DESIGN_SYSTEM.md`.
6. Нужный `PAGE_*.md` / документ страницы.
7. Актуальный файл блока или route, который меняется.

Не начинать сборку страницы или блока без чтения соответствующего брифа.

## 5. Источники правды

- `WORKLOG.md` — текущий статус, незавершённые зоны, журнал правок.
- `SITE_ARCHITECTURE.md` — карта сайта, URL и структура.
- `DESIGN_SYSTEM.md` — цвета, типографика, spacing и визуальные правила.
- `pages/PAGE_*.md` или корневые `PAGE_*.md` — брифы конкретных страниц.
- Глобальные Astro/Codex-правила — единственный источник методики технической сборки.

Если код и бриф расходятся после прямых правок пользователя, сначала актуализировать бриф как `as-built`, затем продолжать работу.

## 6. Локальные правила проекта

- Один блок страницы = один `.astro` файл.
- Route-файл держать тонким: только импорты и порядок секций.
- Namespace классов: `vn-{component}-{element}`.
- Цвета через токены из дизайн-системы, без локального hex.
- React использовать только для интерактивных компонентов.
- Hero-секции учитывать фиксированный header: безопасный верхний отступ обязателен.
- Перед финалом проверять mobile 375px на горизонтальный overflow.

## 7. Формы и заявки

В проекте есть историческое расхождение: часть старых документов упоминает `/api/contact` и Telegram-only обработку, а текущий код может использовать AMS Leads API через `src/lib/leads.ts`.

Перед задачами по формам:

1. проверить текущий код отправки;
2. сверить с `WORKLOG.md`;
3. не менять `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` без прямой команды;
4. секреты не выводить в чат и не переносить в markdown.

## 8. Журналирование

После содержательной правки обновлять:

1. соответствующий `PAGE_*.md` / рабочий документ, если изменился смысл, структура, CTA, текст или визуальное решение;
2. `WORKLOG.md` — что сделано, что проверено, что дальше.

Локальный `AGENTS.md` в проекте не создавать. Единственный `AGENTS.md` находится в глобальных настройках Codex: `C:\Users\User\.codex\AGENTS.md`.
