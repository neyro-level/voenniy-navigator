## 9. Методологические чек-листы

### H2-BRIDGE (для каждого H2)

- Это не техническое название блока: **да**
- Понятна роль блока: **да**
- Есть напряжение / вопрос клиента: **да**
- Есть сильный вывод: **да**
- Есть отличие или механизм: **да**
- H2 ведёт к следующему смыслу: **да**
- H2 не повторяет соседние блоки: **да**

### FAQ-SAFE

- Вопрос звучит как реальный вопрос клиента: **да**
- Вопрос закрывает сомнение, риск или условие: **да**
- Ответ начинается с прямого ответа: **да**
- Ответ не превращается в рекламу: **да**
- Есть ограничение, если оно важно: **да**
- Нет неподтверждённых обещаний: **да**

### Risk Reversal

- Есть блок «Кому не подходит»: **да** (в 03 Eligibility)
- Ограничения называются честно: **да**
- Есть фильтр отсечения: **да**

### Стандарт страницы после нормализации

- Страница выровнена по тому же фрейму, типографике и ритму секций, что и эталонный калькулятор.
- Hero использует шкалу `Hero H1 = var(--fs-display)` и `lead = var(--fs-lead)` без локальных oversized исключений.
- Все секционные H2 приведены к `var(--fs-h2)`, секционные вводные — к `var(--fs-body)`, карточечные H3 — к `var(--fs-h3)`.
- FAQ живёт только через shared-компонент `src/components/sections/FAQ.astro`.
- Финальный CTA живёт только через shared-компонент `src/components/sections/FinalCTALight.astro`.
- Из текстов убраны спорные manual-числа и рискованные формулировки там, где они не были подтверждены как отдельный факт страницы.
