## 1. Роль страницы

Страница закрывает объектный и гео-интент по Краснодару: человек ищет новостройки и квартиры по военной ипотеке, хочет быстро увидеть реальные комплексы, понять сценарий выбора и перейти к первичному разбору ситуации.

Это не общая сервисная страница и не энциклопедия по условиям. Главная роль страницы — показать curated-подборку Краснодара и перевести в осмысленный следующий шаг.

## 4. Что важно в текущей реализации

- Каталог показывает все 12 комплексов сразу.
- Видимого фильтра над каталогом нет: для текущего объёма подборки это признано более чистым UX.
- Карта работает как обзорная навигация по подборке, а не как отдельный продуктовый модуль.
- Страница использует один общий фрейм сайта и не должна ощущаться “шире” или визуально отдельнее главной.
- FAQ на странице обязан жить только через shared-компонент сайта.
- Финальная заявочная секция обязана жить только через shared-компонент главной `FinalCTALight`.

## 5. Стандарт по типографике и паттернам

Для Краснодара зафиксировано as-built правило, которое дальше используется как референс для похожих страниц:

- Hero H1: `var(--fs-display)`
- Section H2: `var(--fs-h2)`
- Card / inner heading: `var(--fs-h3)` или `var(--fs-body)` по роли, без локального завышения
- Lead: `var(--fs-lead)`
- Body: `var(--fs-body)`
- Supportive text: `var(--fs-body-sm)`
- Label / eyebrow: `var(--fs-label)` и `var(--fs-caption)` только для служебных слоёв
- FAQ: только `src/components/sections/FAQ.astro`
- Final CTA: только `src/components/sections/FinalCTALight.astro`

Главное правило: не вводить новые отдельные типографические системы там, где уже есть токены сайта.
