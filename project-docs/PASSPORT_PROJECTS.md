# PASSPORT_PROJECTS — Военный навигатор

## 1. Что это

**Военный навигатор** — сервис выбора новостройки и сопровождения покупки по военной ипотеке.

Сайт помогает военнослужащим и их семьям:

- разобраться в своей ситуации до выбора объекта;
- понять ограничения по банку, бюджету, срокам и формату сделки;
- перейти от первичного разбора к персональному подбору новостройки под задачу.

Михаил Хряпин — экспертное лицо проекта, главный навигатор сервиса и ответственный за первичный разбор / логику отбора.

## 8. Правила позиционирования, тона и CTA

### 8.1. Главный первый шаг

Сайт продаёт не каталог объектов и не абстрактную консультацию, а понятный первый шаг:

> **первичный разбор ситуации перед выбором новостройки по военной ипотеке**

Логика проекта:

1. сначала разбираем задачу покупки;
2. потом определяем ограничения и критерии;
3. потом отбираем подходящие новостройки;
4. затем ведём клиента по маршруту покупки, если он решает двигаться дальше.

### 8.2. Главный CTA

Основные формулировки CTA:

- `Получить подборку`
- `Бесплатный подбор`

Использовать по контексту страницы и блока. Главный акцент — бесплатный подбор новостройки или дома по военной ипотеке.

Допустимые вторичные формулировки:

- `Рассчитать ипотеку` — для калькуляторного контекста
- `Подробнее о сервисе` — для перехода на `/o-servise/`

Не использовать как основной CTA:

- `Записаться на консультацию`
- `Получить бесплатную консультацию`
- `Оставить заявку`
- `Заказать подбор`
- `Подобрать квартиру`
- `Получить первичный разбор`
- `Получить разбор ситуации`

### 8.3. Правила тона после новой рамки

- Главный субъект коммуникации — **сервис Военный навигатор**.
- Михаил Хряпин раскрывается там, где нужен личный экспертный слой, доверие, разбор ситуации и логика отбора.
- Нельзя превращать сайт ни в личный блог Михаила, ни в безликое агентство с абстрактным «мы».
- Безопасная формула: `Военный навигатор помогает…`, `на первичном разборе Михаил уточняет…`, `сервис ведёт…`.
- В юридических, контактных и schema-слоях явно разделять брендовый и legal-контур.

### 8.4. Клиентский язык

Писать понятным языком клиента, без методологической и риелторской воды.

Предпочтительные формулировки:

- `новостройка`
- `квартира`
- `дом / участок`
- `покупка по военной ипотеке`
- `подбор`
- `бесплатный подбор`
- `маршрут покупки`
- `подбор под задачу`

### 8.5. Стоп-слова и рискованные формулировки

Не использовать без подтверждённых оснований:

- `под ключ`
- `комплексный подход`
- `индивидуальный подход`
- `гарантированный результат`
- `гарантия одобрения`
- `лучшие ЖК`
- `ЖК` как основной публичный термин
- `сделаем всё за вас`
- `любая недвижимость`
- `официальный статус`
- `гарантия сделки`

Предпочтительные замены:

- `ЖК` → `жилой комплекс` / `новостройка`
- `консультация` → `подбор`
- `подобрать квартиру` → `отобрать подходящие новостройки`
- `бесплатно` → `без комиссии для покупателя` / `комиссию платит застройщик` / `бесплатно для военного`

### 8.6. Иерархия смыслов

Не смешивать в один уровень:

- цель покупки;
- жизненную ситуацию;
- формат сделки;
- маршрут покупки;
- критерии выбора объекта.

Базовая логика:

| Уровень | Примеры |
| --- | --- |
| Цель покупки | для жизни / как вложение |
| Ситуация | переезд позже / покупка на будущее |
| Формат сделки | лично / дистанционно |
| Маршрут | банк, документы, сроки, участники |
| Критерии | район, срок сдачи, планировка, бюджет |

## 9. Локальные правила проекта

- Один блок страницы = один `.astro` файл.
- Route-файл держать тонким: только импорты и порядок секций.
- Namespace классов: `vn-{component}-{element}`.
- Цвета через токены из дизайн-системы, без локального hex.
- React использовать только для интерактивных компонентов.
- Hero-секции учитывать фиксированный header: безопасный верхний отступ обязателен.
- Перед финалом проверять mobile 375px на горизонтальный overflow.

## 10. Формы и заявки
